# 서버 — 체험자 기록 · 참여 인원 · 이메일 발송

GitHub Pages 는 파일만 내려 주는 곳이라, 방문자 수를 세거나 메일을 보내는 일은 못 한다.
그 일을 무료 구글 Apps Script 하나에 맡긴다. **아직 배포되지 않았다** — 아래 순서대로 본인 구글 계정에서 한 번 만들어야 켜진다.

켜기 전(지금): 체험자 기록은 각자의 브라우저에만 남고, "이메일로 사진 보내기"는 JPG 저장 + 메일 작성 창으로 대신한다.
켠 뒤: 모든 방문자의 기록이 구글 시트 한 장에 쌓이고, 적어 넣은 주소로 빵 사진이 실제로 발송된다.

## 만들기 (약 5분)

1. [sheets.new](https://sheets.new) 로 새 구글 시트를 만든다. 이름은 자유 (예: `Baking Astronaut 체험자`).
2. 메뉴 **확장 프로그램 → Apps Script**. 열린 편집기의 내용을 지우고 [apps-script.gs](apps-script.gs) 전체를 붙여 넣는다. 저장.
3. 오른쪽 위 **배포 → 새 배포**. 유형 **웹 앱**, 실행 계정 **나**, 액세스 권한 **모든 사용자**. 배포.
4. 권한 요청이 뜨면 허용한다 (시트 편집, 내 계정으로 메일 보내기).
5. 나온 **웹 앱 URL** (`https://script.google.com/macros/s/…/exec`) 을 복사해 [../js/config.js](../js/config.js) 의 `endpoint` 에 붙여 넣고 커밋·푸시한다.

스크립트를 고친 뒤에는 **배포 → 배포 관리 → 수정 → 버전: 새 버전** 으로 다시 배포해야 반영된다.

## 어려움 모드 성공 알림

어려움 모드를 통과한 사람이 빵 화면에서 이메일을 적고 **제작자에게 알리기**를 누르면, 이 스크립트를 배포한 계정(= 본인)의 메일함으로
"어려움 모드 성공" 메일이 온다. 본문에 그 사람의 주소·이름·레시피가 있고 빵 사진이 첨부된다. **답장**을 누르면 그 사람에게 간다.
받는 주소는 코드에 적지 않는다 — 스크립트가 배포한 계정의 주소를 스스로 읽는다.
성공 여부는 방문자 브라우저가 보내는 값이라, 마음먹으면 꾸며 낼 수 있다는 점은 감안할 것.

## 관리자가 보는 곳

그 구글 시트의 `players` 시트가 관리자 화면이다. 한 행이 한 명(빵을 구워 낸 사람)이고, 행 수가 곧 참여 인원이다.
시각 · 이름 · 군집 번호 · 레시피 이름 · 난이도가 남는다. 얼굴과 이메일 주소는 남지 않는다.

## 알아둘 것

- **이름은 공개된다.** 체험자가 적은 이름은 다른 방문자의 크레딧에 지나간다. 부적절한 이름은 시트에서 그 행을 지우면 사라진다.
- **메일은 본인 Gmail 로 나간다.** 보낸 사람이 시트 주인 계정이고, 개인 계정은 하루 100통까지다. 스크립트는 하루 80통에서 멈춘다 (`DAILY_MAIL_LIMIT`).
- **주소는 누구나 부를 수 있다.** 웹 앱 URL 은 사이트 소스에 드러난다. 그래서 메일 본문은 고정 문장이고, 받는 주소 형식·첨부 크기·하루 상한을 검사한다. 그래도 누군가 가짜 기록을 넣거나 하루 상한을 소진시킬 수는 있다.
- 이 서버 코드는 실제 배포 환경에서 시험해 보지 않았다. 배포 후 한 번 끝까지 플레이해 시트에 행이 생기는지, 메일이 오는지 확인할 것.
